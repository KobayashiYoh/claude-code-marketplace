# update-packages

pubspecの直接依存パッケージを1つずつ、安全に最新化する。

## 手順

### 0. 事前確認: 制約下限と実解決バージョンのズレ確認

1. `pubspec.yaml` の直接依存(`dependencies`/`dev_dependencies`)の各パッケージについて、指定している制約(下限バージョン)と、`pubspec.lock` で実際に解決されているバージョンを比較する。
2. ズレが大きいパッケージ(制約の下限が実解決バージョンよりかなり古い等)があれば、ユーザーに一覧として報告する。これは制約自体を古いままにしておくと、CI環境などで意図せず古いバージョンが解決されるリスクがあるため。

### 1. パッケージごとの更新サイクル

対象パッケージを1つずつ、以下のサイクルで処理する(全パッケージをまとめて一気に更新しない)。

1. 対象パッケージの最新バージョンを調査する(pub.devのバージョン情報、CHANGELOG、破壊的変更の有無を確認)。
2. `pubspec.yaml` の制約を、調査した最新バージョンに合わせて更新する。
3. `flutter pub upgrade <package>` を実行し、実際に解決されるバージョンを確認する。
4. `flutter analyze` を実行する。
5. `flutter test` を実行する。
6. 結果に応じて分岐する。
   - **成功した場合**: このパッケージの更新をコミットする(`git`プラグインの`commit`スキルの手順に準じ、Whyを重視した簡潔なメッセージで)。
   - **失敗した場合**: `pubspec.yaml`の変更をrevertし、失敗したパッケージ・エラー内容をユーザーに報告してから次のパッケージに進む(あるいはユーザーの指示を仰ぐ)。
7. 次のパッケージへ進む。

### 2. 完了報告

全パッケージ処理後、更新できたパッケージ・スキップ/失敗したパッケージの一覧をまとめて報告する。

## 注意事項

- FVMを使っているプロジェクトでは `flutter` の代わりに `fvm flutter` を使う(プロジェクトの設定・既存スクリプトから使用有無を判断する)。
- 破壊的変更(メジャーバージョンアップ等)を伴う更新は、コード修正が必要になる場合があるため、そのパッケージだけ先にユーザーに相談する。
- コミット前に必ずanalyze/testが通っていることを確認し、通らない状態のまま次のパッケージに進まない。
