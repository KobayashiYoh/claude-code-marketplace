# analyze-pipeline

失敗した(または任意の)Azure DevOpsパイプライン実行のログを取得し、失敗原因を要約する。

## 設定の前提

組織名・プロジェクト名は、ハードコードせずプロジェクト側の設定ファイル(例: `.claude/ado.config.json`)・引数・環境変数から、以下の優先順位で取得する。

1. ユーザーが引数やチャットで明示的に指定した値
2. プロジェクト側の設定ファイル
3. 環境変数(例: `AZURE_DEVOPS_ORG`)

特定できない場合は推測せず必ずユーザーに確認する。

## 手順

1. 対象の実行(run)を特定する。実行IDが指定されていればそれを使い、無ければ「対象パイプラインの直近の失敗した実行」を検索する。
2. `az pipelines runs show` / `az pipelines runs list` 等でログの取得先(タスクごとのログURL)を確認する。
3. 失敗したステージ・タスクのログを取得する。
4. ログから失敗原因を特定する。
   - コンパイルエラー/テスト失敗/依存関係解決失敗/インフラ起因(タイムアウト、ランナー不足等)など、原因のカテゴリを明示する。
   - 該当するエラーメッセージの抜粋を含める。
5. 要約をユーザーに提示する。可能であれば対応方針(再実行で解決するか、コード修正が必要か)も添える。

## 注意事項

- ログ全文が膨大な場合は、エラー箇所を中心に抜粋し、全文をそのまま貼り付けない。
- 過去の類似失敗と比較できる情報があれば言及するが、無理に憶測しない。
