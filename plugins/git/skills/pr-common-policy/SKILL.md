# pr-common-policy

GitHub・Azure DevOpsなど、PRを作成するプラットフォームによらず共通するPR作成時の方針をまとめる。各プラットフォーム固有の `create-pr` スキルは、実行時にこの方針に従う。このスキル単体はユーザーの指示で直接起動されることを想定せず、他スキルから参照される前提。

## 方針

### 1. push確認
現在のブランチとリモートの状態を確認し、未pushの変更がある場合は、ユーザーに確認したうえでpushする。無断でpushしない。

### 2. 本文生成方針
PRのタイトル・本文は、差分・コミットログから機械的に生成するだけでなく、プロジェクト固有のテンプレート(`.github/pull_request_template.md`等)や専用の本文生成スキル(ado環境では`generate-pr-content`)があればそれを優先する。差分から読み取れない意図を推測で断定的に書かない。

### 3. URL報告
PR作成後は、作成されたPRのURLをユーザーに報告する。

## 注意事項

- 各プラットフォーム固有の認証・CLIコマンドの詳細はこのスキルの対象外。各create-pr系スキル側に記述する。
