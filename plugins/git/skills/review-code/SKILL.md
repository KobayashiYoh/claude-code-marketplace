# review-code

指定したAzure DevOpsのPRについて、差分を取得してレビューし、優先度タグ付きのコメントを投稿する。その後もスレッドの状態を追跡し、ユーザーからの返信があれば追加で応答する。

## 設定の前提

組織名・プロジェクト名は、ハードコードせずプロジェクト側の設定ファイル(例: `.claude/ado.config.json`)・引数・環境変数から、以下の優先順位で取得する。

1. ユーザーが引数やチャットで明示的に指定した値
2. プロジェクト側の設定ファイル
3. 環境変数(例: `AZURE_DEVOPS_ORG`)

特定できない場合は推測せず必ずユーザーに確認する。

## 手順

### 1. 差分取得とレビュー

1. 対象PR番号を特定する。`pr-lookup-policy` の方針に従う。
2. `az repos pr show` / 関連コマンドでPRの差分を取得する。
3. 差分内容をレビューし、指摘事項をまとめる。各指摘には優先度タグを付ける(例: `[must]` 修正必須 / `[should]` 推奨 / `[nits]` 些細な指摘 / `[question]` 確認)。
4. レビューコメントをPRに投稿する(`az repos pr` 系のコマンドでスレッドを作成)。

### 2. スレッド状態の追跡

1. 各コメントスレッドの状態(`active`/`pending`/`fixed`/`wontFix`/`closed` 等、Azure DevOpsのスレッドステータスに準じる)を記録する。
2. 定期的に(またはユーザーの指示に応じて)スレッドの状態を再取得し、ユーザーからの返信が付いていないか確認する。
3. ユーザーの返信を検知した場合、その内容に応じて追加の応答を行う。
   - 合意された修正が反映されていればスレッドを `fixed`/`closed` に更新することを提案する。
   - 反論や質問であれば、それに対する見解を返信する。

## 注意事項

- 指摘は「見解」と「結論」を分けて書き、なぜその指摘をするかの理由づけを明確にする。
- スレッドを一方的にcloseせず、必ずユーザー(またはPR作成者)の反応を踏まえて状態を更新する。
- 認証情報の平文保持・出力は行わない。
